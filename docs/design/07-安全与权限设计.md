# 07 安全与权限设计

## 1. 凭证总账

| 凭证 | 类型/Scope | 存放 | 用途 | 轮换 |
|---|---|---|---|---|
| `GITHUB_TOKEN` | 临时，`contents:read` + `packages:write`，单次运行 | 平台托管，无需配置 | 业务仓库推镜像到 GHCR | 短时效自动失效 |
| `GITOPS_PAT` | fine-grained，**仅 deploy 仓库** `Contents: Read/Write` | GitHub org secrets | deploy job 跨仓库 bump tag | 季度；泄漏只影响 deploy 仓库内容（可审计可回滚） |
| `GHCR_PULL_TOKEN` | **classic** PAT，`read:packages` | org secrets + sealed 进集群 | k3s 节点/虚机拉私有镜像 | 半年；轮换需重新 kubeseal + 更新 secret |
| `VM_SSH_KEY` | 虚机部署用户私钥（建议仅该用途） | org secrets | 虚机通道 SSH | 季度 |
| sealed-secrets 私钥 | 集群内生成 | **集群 etcd**（需异地备份） | 解密 SealedSecret | 主动轮换可选；**丢失 = 所有密文重做**，必须备份。备份文件**严禁提交任何 Git 仓库** |
| Argo Git 只读 PAT | fine-grained，仅 `cicd-infra` + `deploy` 两仓库 `Contents: Read-only` | **集群内** Secret（argocd ns，`argocd.argoproj.io/secret-type: repository`） | Argo CD 拉取私有 Git | 半年，与 GHCR PAT 同期换 |

> fine-grained PAT 目前不支持 GHCR 拉取（packages read），所以拉取侧必须 classic PAT——这是唯一放宽的点，用最小 scope（仅 read:packages，不勾选其他任何权限）补偿。

## 2. GitHub 侧配置

### 2.1 组织级 secrets（Settings → Secrets → Actions → Organization）

`GITOPS_PAT`、`GHCR_PULL_USER`、`GHCR_PULL_TOKEN`、`VM_SSH_KEY`。
可访问范围：全部仓库（业务仓库要 `secrets: inherit` 透传）。

### 2.2 Environments（部署门禁）

| 环境 | 保护规则 |
|---|---|
| `dev` | 无（隐式创建即可） |
| `prod` | Required reviewers：指定发布审批人（≥2 人，避免单人瓶颈） |

### 2.3 deploy 仓库分支保护

main：要求 PR + ≥1 review + 分支最新。配置与发布审计统一收敛到 PR/commit 历史。

### 2.4 cicd-infra 仓库分支保护

main：要求 PR + review。发布 = 打 tag（v1 指针策略见 02 文档第 8 节）。

### 2.5 GHCR 包策略

- 组织 Packages 改进权限：成员可推；Actions 可写
- 包默认 **internal**（org 内可见）
- 按需对单个包收紧：包设置 → manage access

## 3. 集群侧（k3s）

| 项 | 策略 |
|---|---|
| Argo CD 访问 | UI 默认仅 port-forward / 内网 ingress 暴露；admin 仅平台维护者；服务负责人只读 |
| Argo CD 与 GitHub | 走 https 拉取，无需凭证（deploy 仓库私有时配只读 deploy key 或只读 PAT） |
| namespace 隔离 | 每服务每环境独立 namespace（`<svc>-<env>`），默认 NetworkPolicy 可选加固 |
| kubeconfig | **不进 GitHub、不进任何仓库**；仅运维本地与集群节点 |

## 4. 攻击面对比（push 模式 vs 本方案 pull 模式）

| 攻击面 | push 模式（弃用） | 本方案 |
|---|---|---|
| GitHub 凭证泄漏 | CI 持集群管理员 kubeconfig → 集群裸奔 | 最坏改 deploy 仓库（PR 审计 + 可回滚） |
| 仓库投毒（改 values 塞恶意镜像） | 同样存在 | 分支保护 + PR review 拦截 |
| 镜像投毒 | 同样存在 | sha 固定 + GHCR 私有 + 后续可加 cosign 签名验证 |
| 集群凭证外泄面 | GitHub secrets、CI 日志、runner | 仅集群节点与运维本地 |

## 5. 审计与可观测

- **发布审计**：deploy 仓库 commit 历史（`deploy(env): svc -> sha`）+ GitHub Actions 运行记录
- **配置审计**：deploy 仓库 PR/文件历史
- **集群实际状态**：Argo CD UI（谁偏离、何时同步）
- 建议开启 GitHub org 的 audit log 归档（如有付费版）

## 6. 后续加固路线（按需）

| 项 | 时机 |
|---|---|
| 镜像签名（cosign + Argo CD 验签） | 供应链安全要求出现时 |
| Argo CD 通知（Slack/飞书 webhook） | 发布可见性需求 |
| NetworkPolicy 默认模板 | 服务间调用管控需求 |
| Vault / ESO | 密钥规模与动态密钥需求（数据库短时凭证等） |
| runner 加固/自托管 runner | 合规要求 |
